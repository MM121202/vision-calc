# vision-calc A/B 实验记录

> 改进前（基线 A）vs 改进后（版本 B）的对照实验。实验日期：2026-11-23。
> 对照原则：只改要验证的模块，其余条件严格一致（同一台机器、同一测试脚本、同一批用例）。

## 1. 实验环境

| 项目 | 值 |
|---|---|
| 机器 | Lenovo 笔记本（Windows，本机沙箱环境） |
| 运行时 | Node.js 22.22.2（vm 沙箱驱动页面脚本） |
| 测试脚本 | `tests/run_tests.js`（DOM 桩 + 独立公式重算交叉验证） |
| 用例数 | 20 个标准选型场景（含已知答案的教科书案例） |
| 延迟测法 | 单次 `compute()` 平均耗时，n=3000 |

## 2. 基线 A（改进前，commit 03c587e 的 index.html）

**测试脚本对基线的兼容处理**：基线 `compute()` 直接读 DOM，测试桩按同样的输入 id 驱动。基线无 `calc()` 纯函数、无 `rDiff`/`cmpPanel` 节点，新功能检查项在基线上按"无"计。

| 指标 | 基线 A 实测 |
|---|---|
| 20 用例公式正确性 | **20/20** |
| 单次重算延迟 | **0.074 ms**（n=3000） |
| 核心校验维度 | **5 项**：分辨率选型 / 焦距选型 / 解析力 / 景深 / 透视·远心判定 |
| 光学衍射极限校验 | 无 |
| 双方案对照 | 无 |
| URL 参数复现 | 无（刷新即丢输入） |
| 选型报告导出 | 无 |
| 依赖 | 0（单文件 index.html） |

## 3. 版本 B（改进后）

| 指标 | 版本 B 实测 | 相对 A 变化 |
|---|---|---|
| 20 用例公式正确性 | **20/20** | 不变（重构为纯函数后原公式零回归） |
| 新功能用例 | **6/6** | +6（衍射校验 / calc 纯函数 / 双方案 / URL 复现 / 报告导出 / 衍射报警物理正确性） |
| 单次重算延迟 | **0.092 ms**（n=3000） | +0.018 ms（+24%，绝对值仍远低于人眼感知阈值 16ms，可忽略） |
| 核心校验维度 | **8 项** | +3：+衍射极限校验 +双方案对照建议 +复现/导出 |
| 依赖 | 0 | 不变（仍单文件、零依赖、离线可用） |

**B 版新增功能明细**（6 项检查全部通过）：
1. 衍射极限校验输出（rDiff 节点，含上限 lp/mm 与余量倍数）
2. `calc()` 纯函数可独立驱动（教科书案例 f=12mm、130万相机，与页面输出一致）
3. 双方案对照面板渲染并给出"建议选方案 A/B"
4. URL hash 参数复现（`#f=40&p=0.15&...`，刷新/分享保留整套输入）
5. 选型报告导出（含边界声明）
6. 衍射不足报警的物理正确性（850nm+小光圈+高精度场景必须报警）

## 4. 结论边界（重要）

- 本实验的"正确性"指**计算结果与独立重算公式一致**（20 用例交叉验证），**不代表实机成像验证**——未做过真实相机+镜头的实拍标定，不能声称"选型 100% 准确"。
- 延迟差异 +0.018ms 属于噪声量级，不作为收益主张。
- 衍射极限采用非相干成像截止频率近似 `1/(λ·F)`，未含 MTF 曲线与像差，结论为方案筛选参考。

```bash
git checkout <改进前commit> && node tests/run_tests.js

```
